1.1  What FxmeNet is

FxmeNet lets your digital audio workstation (DAW) run its effects on another computer. In the DAW you insert one plugin, called FxmeNet. Behind it, a chain of plugins runs on a server (the program fxmenet-server) on the same local network. The audio goes to the server and comes back; the DAW sees one ordinary plugin, and compensates the delay it reports, as it does for any plugin with latency.

The reason is simple: a session with many heavy plugins can exhaust the CPU of the computer that runs the DAW. A second machine, even an old one, can take that load. In our tests (chapter 7), 24 tracks with 17 plugins each used 75 % of the client’s processor when processed locally, and 20 to 25 % through FxmeNet.

The server is a console program. It needs no screen, no desktop session and no keyboard, so it can live in a cupboard or a rack, and it can run on a different operating system than the DAW.

1.2  How it works

FxmeNet has two parts.

  • The client is the FxmeNet plugin (VST3 and AU), loaded in the DAW. It has the editor you work with.
  • The server is fxmenet-server. It loads the VST3 plugins you ask for and processes the audio.
   Your DAW (client)                          Server 
 +---------------------+                +-------------------+ 
 |  track 1: FxmeNet --+--- audio UDP --->  session 1: chain | 
 |                     <--- audio UDP ---+  (plugin, plugin) | 
 |  track 2: FxmeNet --+--- audio UDP --->  session 2: chain | 
 |                     <--- audio UDP ---+                   | 
 |  every instance  ---+--- control TCP -->  plugin list,    | 
 |                     <-------------------  parameters, ... | 
 +---------------------+                +-------------------+

Each instance of FxmeNet in your project opens one session on the server, with its own chain of plugins. Two kinds of traffic flow:

  • Audio, in small blocks of N samples, over UDP, in both directions. A reply that is late is replaced by a short fade to silence and back (the block is concealed); this is how a network that is sometimes slow stays inaudible most of the time.
  • Control, over TCP: the list of plugins, adding and removing plugins, parameters, saving and restoring state.

The network budget D says how many blocks of time a reply has to come back. The latency that FxmeNet adds is about N times D samples, plus what the DAW’s own block size adds. Chapter 7 explains how to choose them.

1.3  What you see: native editors

When you work on a plugin that sits on the server, you do not look at a picture of a remote window. If the same plugin is installed on the client computer, FxmeNet opens the plugin’s own editor locally, and keeps it in step with the copy on the server. Knobs respond at once, and the editor scales with your screen. If the plugin is made for FxmeNet (see chapter 9), its meters and analysers show the server’s real signal. Plugins that are not installed on the client still work, with a generic panel of sliders. These cases are the tiers of chapter 8.

1.4  What FxmeNet is not

  • It is not a way to play live through a very low latency. The added latency is a few milliseconds at best (a few tens of milliseconds for heavy loads). It suits mixing and production; for live monitoring, keep latency-critical plugins local.
  • It is for a local network you control. The traffic is not encrypted and the server does not ask for a password. Do not expose its ports to the internet.
  • The server hosts VST3 effects. Instruments are not offered.
  • It does not make plugins sound different: the server runs the same plugin code your DAW would run.

1.5  What you need

A server.

A computer with spare CPU and a wired network connection. Linux is the reference platform (our tests use Ubuntu 24.04).

A client.

A DAW on Windows, macOS or Linux that hosts VST3 (or AU on macOS). The tests used Reaper on Windows.

A network.

A wired gigabit network between the two machines. Wi-Fi works badly for audio. A stereo track at 44.1 kHz uses about 3 Mbit/s in each direction (chapter 12).

The plugins.

The plugins you want to run must be installed on the server. For their own editors on the client, install the same version there too.

1.6  Terms used in this manual

Block size N

Samples sent to the server at a time (32 to 1024).

Network budget D

Blocks of time allowed for a reply to come back (1 to 8).

Session

One instance of the FxmeNet plugin, connected to the server, with its chain.

Chain

The plugins of a session, processed in an order you choose, and optionally wired by the routing (chapter 6).

Concealed block

A block whose reply came too late, replaced by a short fade out and in.

A fuller list is in the glossary (chapter 13).

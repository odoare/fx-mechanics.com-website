2  Quick start

This chapter takes you from nothing to audio going through a plugin on the server, in about ten minutes.

2.1  Get the software

Download the files for your system from the Releases page of the project on GitHub, https://github.com/odoare/FxmeNet/releases. Each release offers an installer and, for those who prefer to copy files by hand, a plain archive with the same content. Install the server on the computer that runs the effects, and the plugin on the computer that runs the DAW (they can be the same computer). The installers let you choose.

Windows

Run FxmeNet-X.Y.Z-Windows-Setup.exe and choose Plugin only, Server only or both. The plugin goes to C:\Program Files\Common Files\VST3, and the server and fxmenet-top to C:\Program Files\FxmeNet, with a Start menu entry for this manual. Two options are offered: adding the folder to the PATH, and allowing the server through the Windows firewall (UDP 54320 and 54321, TCP 54322). The installer is not signed, so Windows may show a warning on first run (choose More info, then Run anyway). Without the installer, unzip FxmeNet-X.Y.Z-Windows-x86_64.zip and copy the files yourself.

macOS

Open FxmeNet-X.Y.Z-macOS.pkg and choose the parts to install: the VST3 plugin (in /Library/Audio/Plug-Ins/VST3), the Audio Unit (in ... /Components), and the server with fxmenet-top (in /usr/local/bin). The programs are universal (Apple silicon and Intel). The package is not signed or notarized, so macOS may refuse to open it; in that case use Open Anyway in System Settings, Privacy & Security. The same files are in FxmeNet-X.Y. Z-macOS-universal.zip.

Linux

On Debian and Ubuntu, install fxmenet_X.Y.Z_amd64.deb with sudo apt install ./fxmenet_*_amd64.deb. It puts the programs in /usr/bin, the plugin in /usr/lib/vst3, and an example systemd unit in /usr/share/ doc/fxmenet. On other distributions, unpack FxmeNet-X.Y.Z-Linux-x86_64. tar.gz and run ./install.sh (for your user: ~/.local/bin and ~/.vst3) or sudo ./install.sh --system (/usr/local/bin and /usr/lib/vst3). ./install.sh --uninstall removes them.

Every installer also puts the PDF manual next to the programs.

Note.  The installers and archives are new, and not all of them have been tried on every system. If one does not work for you, please tell us.

2.1.1  Building from source

You need a C++17 compiler and CMake 3.22 or newer. JUCE and FxmeTools are downloaded at the versions the project pins; if clones named JUCE and FxmeTools sit next to the FxmeNet folder, those are used instead (-DFXME_USE_SIBLINGS=OFF forces the pinned versions). From the FxmeNet folder: 

cmake -S . -B build 
cmake --build build --target FxmeNetServer -j2 
cmake --build build --target FxmeNetPlugin_VST3 -j2 
cmake --build build --target FxmeNetTop -j2

This gives three programs, inside the build folder: the server (fxmenet-server), the plugin (FxmeNet.vst3) and the monitoring tool (fxmenet-top, chapter 4). Copy them where the installers would put them.

2.2  Install the plugins on the server

The server offers the VST3 effects it finds in its plugin folders: the standard VST3 folders of the machine (on Linux, typically ~/.vst3, /usr/lib/vst3 and /usr/local/lib/vst3), plus any you add (section 3.3). Install the plugins you want to use there, the way you would on any computer.

2.3  Start the server

On the server machine, in a terminal: 

fxmenet-server

The first time, the server examines every plugin it finds (this can take a minute for a large collection) and then logs the list, ending with lines like: 

2026-11-10 14:02:11  48 plugins (48 examined, 0 from the cache, 0 failed) 
2026-11-10 14:02:11  listening: control TCP 54322, audio UDP 54321, discovery UDP 54320

Later starts are quick, because only new or changed plugins are examined again. Leave the server running. Stop it with Ctrl+C.

Note.  Your computers’ firewall must let the three ports through on the local network (chapter 12). Under Ubuntu’s ufw, for example, allow 54320 to 54322.

2.4  Install the plugin on the client

If you used an installer, the plugin is already in place; otherwise copy FxmeNet.vst3 to your VST3 folder (section 2.1). Then let your DAW rescan its plugins.

On macOS the plugin is also built as an Audio Unit. The AU is not notarized, so macOS may refuse to load it at first; the README on the project’s GitHub page explains what to do. The AU has not been tested yet, and feedback is welcome.

2.5  Your first chain

1.
In the DAW, add FxmeNet to a track, as an effect.
2.
Click Find. The server answers on the local network; choose it in the list. (If it does not appear, type its address in the field, for example 192.168.1.20.)
3.
Click Connect. The status line next to the button says when the session is ready.
4.
The list SERVER PLUGINS shows what the server offers. Type a few letters of a plugin’s name in the Filter field, and press Return (or double-click a plugin) to add it to the chain.
5.
Play. The audio goes through the server. The plugin’s controls appear in the right-hand panel; its parameters are also listed in the DAW as automation parameters.

The line at the bottom of the editor shows the latency that FxmeNet reports to the DAW and the count of concealed blocks. On a healthy network the count stays at zero, or nearly.

Tip.  To see what the server is doing, open fxmenet-top in a terminal on the server (chapter 4). It shows each session, the server’s load and the traffic.

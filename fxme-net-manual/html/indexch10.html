10.1  The plugin does not find the server

  • Is the server running? On its machine, fxmenet-top should show it. If not, start fxmenet-server.
  • Does Find show nothing? Discovery uses a broadcast, which does not cross routers or most VPNs, and is blocked by some firewalls. Type the server’s address in the field instead.
  • Can the client reach the server’s ports? Check the firewall on the server (TCP 54322, UDP 54321 and 54320) and, on the client, that the DAW is allowed to use the network.
  • Is a second server running on the same machine? Only one can answer Find; give the other one a different port set, or no discovery.

10.2  The plugin I want is not in the list

  • It must be a VST3 effect installed on the server, in a folder the server searches (section 3.3).
  • Look at the server’s log (or the 3 view of fxmenet-top) for “skipped”: a plugin that crashed or hung when loaded is left out until it changes.
  • You installed it while the server ran: rescan with r in fxmenet-top, then reconnect the plugin.
  • The list is filtered: clear the Filter field.

10.3  A plugin shows tier T0 when I expected T1

The plugin must be installed on the client, in a folder the client scans, in the same version. Hover over the row for the reason. Use Rescan or Folders… in the Settings tab (chapter 8).

10.4  Concealed blocks, dropouts or clicks

Look at where the problem is.

1.
In fxmenet-top, is the server’s CPU high, or a session’s load bar red? Then the server is overloaded: use larger blocks (1024×2), reduce the load, or use a faster server.
2.
Does a session’s lost count rise? Requests do not reach the server in time: look at the network (wired? other traffic? a switch that drops packets?).
3.
Does send errors rise in the server’s log? The kernel drops replies: raise the socket buffers (section 7.4).
4.
Do the threads show TS instead of RR in the check of section 7.4? Give the audio threads real-time priority.
5.
Only the client’s concealed count rises while the server’s counts are zero? Replies are delayed on their way back, or the server stalls briefly. Raise D by one.

If clicks persist, enable Log transport events in the Settings tab, reproduce the problem, and keep fxmenet-client-events.log and the server’s log together for the report.

10.5  Silence at start, stop or jump

This is the Silence in-flight audio at reset option of the Settings tab doing its job: for the length of the latency after a restart, nothing is heard from the plugin, as with a local plugin whose delay line is cleared. Turn the option off to hear what was still in flight.

10.6  The audio is late compared with other tracks

The DAW compensates for the latency that FxmeNet reports. If a track is still late, check that the DAW’s plugin delay compensation is on and that the DAW applies it to this track.

10.7  Everything stops when the server restarts

The plugin reconnects by itself and rebuilds the chain on the server. If the server does not have the same plugins any more, the affected plugins show an error in the chain. While the server is away, the sound becomes dry at once; when the server is back, the processed sound returns. Restarting the server during playback was tested, without audible glitches.
